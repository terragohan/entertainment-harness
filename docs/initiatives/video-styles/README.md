# Video styles — four new presentation modes for chapter videos

Status: **done** (2026-09-27 — all four modes shipped and gated; motion's live
Runway render deliberately excluded, see Phase D)

## Goal

Four new `[video] mode` values alongside `kenburns`/`scroll`, all selectable
from the CLI (`--video-mode`), config, and the desktop app's video-mode
dropdown:

1. **`slideshow`** — static full-page crops; pages within a segment dissolve
   into each other (xfade), hard cuts between segments. No zoom, no pan.
2. **`cards`** — caption cards (moment label + segment text over a blurred
   cover/dark gradient, via `video/cards.py`), one card per segment with a
   gentle zoom. This is the mode that makes **books** renderable as chapter
   videos (they have no pages).
3. **`panels`** — guided view: each beat crops to its grounded panel region
   and Ken-Burnses within the crop. Reuses the scroll mode's grounding stage
   (stage 3.5) and the panel-first path's stamped regions.
4. **`motion`** — per-segment clips generated by the configured video-gen
   provider (`[video_gen] provider`, `local` or `runway`), following the
   short pipeline's provider seam. `local` degrades to Ken Burns assembly.

## Non-goals

- No changes to script/TTS/page-assignment stages except where a mode
  requires it (cards skips page picking; panels reuses grounding).
- No new provider implementations (runway exists; no others added).
- No live paid Runway renders as gate evidence — motion's gate is code +
  mocked-provider tests only; a real render needs the user's API key and OK.
- No cross-segment crossfades (they break narration/subtitle alignment math;
  slideshow dissolves only *within* a segment's page set).
- No changes to the short/tiktok pipeline — it already has its own cards and
  provider paths.

## Rationale

`kenburns` and `scroll` both assume manga pages. Books are unrenderable as
chapter videos today (cards fixes that — the short pipeline proves the card
renderer). Readers asked for calmer (slideshow) and more guided (panels,
motion) presentations. All four modes reuse existing machinery: cards.py,
grounding.py anchors, gen/ providers — the work is dispatch, not new tech.

## Design

Mode resolution in `build_video` (`video/pipeline.py`): CLI `--video-mode` →
`[video] mode` → default. `render_state.json` already keys renders on mode,
so switching modes re-renders for free. `VIDEO_MODES` gains the four values;
server validation and the UI dropdown pick them up (UI has its own const).

- **slideshow**: stage 3 unchanged (vision page picking). Assembly: pages of
  one segment render as a single clip built from an ffmpeg `xfade` chain —
  per-page hold time is extended so the chain's total length equals the
  segment slot exactly (`per_page = (slot + (n-1)*F)/n`); single-page
  segments get a static scale/crop clip. Hard cuts between segments keep
  audio/subtitle alignment exact. Motion stamped `slideshow`.
- **cards**: stage 3 replaced by `render_cards(segments, title, workdir,
  size=resolution, cover=<work cover.*>)`; `seg.pages=[i+1]`,
  `seg.motion="zoom_in"`; card paths become the assembly page list. Page-dir
  existence check and colorize/translated are skipped. Cards are cleared
  whenever the script regenerates (`clear_downstream(narration=True)`).
  Books: when kind == "book" and no explicit mode was chosen (CLI flag unset
  and config still the default `kenburns`), cards is auto-selected with a
  log line; an explicitly chosen non-cards mode on a book errors clearly.
- **panels**: stage 3.5 grounding runs for `scroll` *and* `panels`. Assembly:
  validated anchors (`_segment_anchors`) — each hold anchor's box is cropped
  from the page (normalized coords, degenerate boxes fall back to full page),
  each crop Ken-Burnses for `slot/n` seconds, hard cuts between anchors; pan
  anchors and ungrounded segments fall back to the kenburns per-page path.
  Motion stamped `panels`.
- **motion**: stage 3 unchanged. Assembly: provider =
  `get_video_gen_provider(config.video_gen.provider, config)`; if
  `provider.animated`, each segment's first assigned page goes through
  `provider.generate_segment(...)` and `seg.duration_s` is re-stamped from
  the clip (short.py's established pattern); non-animated providers fall back
  to normal assembly. `videos.video_gen_provider` records the provider.

## Phases

### Phase A — slideshow (gate: tests + full suite green)

- `assemble.py`: `build_xfade_clip(pages, slot, resolution, dest)` + dispatch
  in `assemble()` when `seg.motion == "slideshow"`.
- `pipeline.py`: `VIDEO_MODES` += `"slideshow"`; motion restamp knows it.
- Tests: xfade command/duration math (mocked ffmpeg), assemble dispatch.

### Phase B — cards + books (gate: tests + full suite green)

- `pipeline.py`: cards stage-3 replacement, page-check bypass, book
  auto-select/error, cards invalidation on script regen.
- `pipeline.py` `clear_downstream`: clear `cards/` when narration resets.
- Tests: book + cards renders without pages (mocked TTS/ffmpeg); explicit
  kenburns on a book errors; auto-select logs and proceeds.

### Phase C — panels (gate: tests + full suite green)

- `pipeline.py`: grounding stage condition `mode in ("scroll", "panels")`;
  motion restamp; `wanted["grounded"]` for panels.
- `assemble.py`: panel-crop clip path for `seg.motion == "panels"`.
- Tests: anchored segment renders panel crops (mocked ffmpeg); ungrounded
  segment falls back to kenburns path.

### Phase D — motion (gate: tests + full suite green; NO live Runway spend)

- `pipeline.py`: provider dispatch in stage 4 for `mode == "motion"`;
  `_record_video(video_gen_provider=provider.name)`.
- Tests: animated fake provider → generate_segment called per segment,
  durations re-stamped, provider recorded; local provider → normal assembly.

### Phase E — surface + release (gate: typecheck, smoke, package, frozen checks)

- UI `VIDEO_MODES` const (labels for the four new modes), CLI `--video-mode`
  help, `docs/design.md`, this file's evidence.
- `cd ui && bun run typecheck && bun run smoke && bun run package`;
  `ui/resources/backend/eh-serve/eh-serve --check-imports` and `--check-tts`.
