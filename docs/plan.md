# Entertainment Harness — Execution Plan

Full execution plan for the manga recap harness, structured as **progressive confidence building**: each phase ends in a gate you verify before proceeding. See `docs/design.md` for architecture, schema, model/quantization options, and rationale.

## Sample manga: Kenja no Mago (Wise Man's Grandchild)

- MangaDex ID: `835feda4-2db0-4753-8249-4575a3ceffe2` (main series, ongoing, 2016–)
- **Verified via API (2026-08-22): no English chapters are hosted.** Of the 58 hosted chapters, 54 are `pt-br` and 4 are `es-la` (incl. ch 86). The `en` language tag on the series is stale.
- This is workable and actually useful: Qwen3-VL is multilingual, so the pipeline reads Portuguese pages and produces **English recaps** — a real stress test of the model instead of a toy one. If a pure-EN sample is preferred as a baseline, pick any EN-hosted series via `eh search`.
- Chapter sizes (pt-br): ch 0 = 16 pages (fast spike material), ch 1 = 53 pages, ch 2 = 54, ch 3 = 53 (full pipeline test).
- Ground truth for judging recaps: ch 1 covers Shin's reincarnation and childhood training under Merlin. A good recap must get the protagonist's name (Shin) and the chapter's key events right.

## Phase 4 — Video pipeline (~1–2 days) — ✅ DONE 2026-08-23

15. `video/script.py`: ch 1 recap → segmented narration script.
    **Gate: PASSED** — 12 segments, 433 words → 172 s narrated (2.9 min); each segment tagged with a story moment ("Shin hunts the boar", "Merlin explains nonchanter", …). Needed two prompt-tightening rounds: qwen3:4b under-writes segments (~13 words each) unless given a hard minimum ("at least 30 words", "420-550 words total").
16. `video/tts.py`: Kokoro-82M (fallback: macOS `say`); per-segment WAVs, audio durations authoritative.
    **PASSED** — Kokoro runs via `kokoro-onnx` (the `kokoro` pip package fails to build on Python 3.13: spaCy→curated-tokenizers has no cp313 wheel). Model files auto-download to `data/tts/` on first use. Durations are read back from the rendered WAVs.
17. `video/visuals.py` (full pages + Ken Burns; panel crops deferred per design) + `video/assemble.py` (ffmpeg `zoompan`, concat, mux, SRT subtitles).
    **Gate: PASSED** — `out.mp4` for ch 1 (1920x1080 h264@30 + aac + mov_text subs, 172 s, A/V durations within 7 ms); spot-checked frames show the right page for the narration beat. Page picking: vision model reads labeled contact sheets (12 pages/sheet, 5 sheets for 53 pages) and maps segments → pages.
    - **Learning:** this ffmpeg (homebrew 8.0.1) has no libass/drawtext — subtitles are embedded as a mov_text soft track instead of burned in.
    - **Learning:** the vision model over-assigns pages (segment 0 got 9 pages chapter-wide). v1 used only the first assigned page per segment, which camped the whole video on the early chapter (ch 1 showed only pages 4-12 of 53). Fixed: `_segment_pages` shows all assigned pages, duration split evenly, capped at ~1 page per 2.5 s with even spacing across the range; script density raised to 14-20 segments / 500-650 words. Rebuilt ch 1 video: 30 of 53 pages shown, full-chapter span.
18. `eh video` command + `videos` table + staged artifact caching.
    **Gate: PASSED** — second run: all 4 stages "cached", no model/TTS/ffmpeg work, single videos row (`kokoro`, script model attribution, duration). Re-running an upstream stage invalidates downstream artifacts (`_clear_downstream`), so script edits trigger narration+assembly rebuilds but nothing else.

## Phase 6 — Books, comics & TikTok short-form videos — ✅ DONE 2026-08-24

- **Import layer** — `importer.py` + `eh import <path-or-url> [--title] [--kind]`: books (EPUB via stdlib zip/XML/HTML parsing, TXT/MD split on chapter headings with ~4 000-word fallback chunks) into `data/books/<series-id>/ch-NNN.txt` (+ cover); comics (CBZ/CBR-via-system-unar/image-folder) extracted into the existing `data/manga/<series>/<chapter>/` layout. URLs must be direct file links (500 MB cap; HTML refused). `series.kind` column (`manga`/`book`/`comic`) added via migration-on-open.
  - Live gate: PASSED — Gutenberg EPUB by URL (The Yellow Wallpaper: 1 part + cover) and a CBZ built from `samples/kenja-ch0/` (16 pages) both imported with correct rows.
- **Book recap path** — `recap.py` summarizes stored text parts with the text-role model only (no vision pass), ~3 000-word chunks + combine, rolling context identical; source clients are now constructed lazily so `source="import"` works.
  - **Learning (two real bugs caught live):** the first `BOOK_BATCH_PROMPT` never included the excerpt text — the small text model then answered from *training memory* (a plausible Yellow Wallpaper recap with zero input, violating the no-outside-knowledge rule) or refused intermittently. The excerpt is now embedded in the prompt and a test asserts it. Also: combine/context prompts must carry the "Never refuse; part/section numbering is a file-splitting artifact" line — qwen3:4b otherwise meta-comments on the numbering instead of summarizing (same lesson as the manga COMBINE_PROMPT in Phase 2).
  - Live gate: PASSED — book recap + rolling context produced text-model-only (accurate: narrator, John, the wallpaper; the context's last sentence notes the Gutenberg license tail — harmless noise from the final excerpt). Comic recap via the existing vision path (accurate truck-kun opening).
- **`eh tiktok <series>`** — `video/short.py`: whole-work 1080x1920 ~60–90 s video from the rolling series context (hook-first 8–12 segment script), reusing script/tts/visuals/assemble. Comics/manga: pages flattened across chapters for the existing page-assignment stage (`assign_pages` gained a `where` label); books: generated caption cards (`video/cards.py`, Pillow, blurred cover or gradient backdrop). Faster cuts (`min_page_seconds` 1.5, parameterized in `assemble.py`). Whole-work videos recorded in `videos` with NULL chapters; `eh play <series> --tiktok`.
  - Live gate: PASSED — book: 77 s, 1080x1920, A/V within 82 ms, hook-first title card over blurred cover; comic: 69 s, A/V within 31 ms, frames span the truck-kun opening through Merlin healing the baby. Re-runs fully cached (both). One transient: a concurrent recap+tiktok run starved Ollama and the first comic tiktok attempt timed out in script generation — a resource-contention flake, not a code bug (retry alone: 3.7 min).
  - 141→147 tests green.
- ✅ DONE 2026-08-24: **`eh recap --translated`** — translate-first recapping: any source language becomes eligible (language filter dropped in this mode), chapters not already in `[library] lang` are translated (`translate_chapters`, now with lazy client construction) before the recap reads the English overlay pages; `eh recap --translated --video` renders with translated pages too. Recaps/context/progress use the same tables, so it chains onto existing recaps. Live gate: PASSED — ch 25.5 (pt-br, 10 pages) translated (6–12 bubbles/page) then recapped from the overlays in ~4.5 min.
  - **Learning (context corruption + repair):** ch 25.5 turned out to be a *crossover chapter from a different manga* (Zack/BLUE SPHERE, not Kenja no Mago). The context model correctly noticed the mismatch — but its meta-commentary ("cannot be incorporated… story so far remains unchanged") was stored verbatim, **destroying the accumulated 298-word context**. Fixes: `CONTEXT_PROMPT` now says "unrelated bonus chapter → output the previous story-so-far unchanged", and a guard (`_suspicious_context`: meta-phrases + length collapse) keeps the previous context instead of overwriting; recap/progress still advance. Second repair attempt taught another lesson: **one-shot whole-library compression (29 recaps, ~4 500 words) makes qwen3:4b hallucinate wholesale** (invented canon, wrong protagonist) — the incremental chain is the only reliable mechanism at this model size. Context rebuilt by replaying recaps 0–25 through the chain with the guard active (gate: PASSED — final context covers Shin/Merlin/the academy arc through ch 25, 324 words).
- Also added 2026-08-24: `eh remove <series> [--keep-files] [-y]` — deletes a series with its chapters/recaps/translations/videos and (unless `--keep-files`) local files, after an interactive confirmation; HF-store backups untouched.
- ✅ DONE 2026-08-24: **judge eval loop** (`judge.py`, `[models.judge]` role defaulting to the text model) — the chapter recap and the context update are judged (faithfulness/cohesion/continuity/form; context also checks preservation + the unrelated-crossover pass case) and regenerated with the judge's issues fed back, bounded at 3 attempts. A still-failing recap keeps its **first** attempt (stored with a warning); a still-failing context update keeps the previous story-so-far (the regex backstop stays). Unparseable judge output = pass. `eh recap --no-judge` disables. 161 tests green.
  - **Learning (judge false-rejection + feedback poisoning):** the first live judged run (ch 0, translated) exposed the loop's own failure mode — qwen3:4b as judge false-rejected a perfectly good recap ("no story content", wrong), the feedback-poisoned retry over-complied and produced an empty recap, and the confused judge passed *that*. Two fixes: (1) judge prompts now demand a quoted offending phrase for every reported issue ("if you cannot quote it, do not report it"); (2) on persistent failure the loop returns the **first** attempt, not the last — retries amplify a bad critique. If false rejections persist, pin a stronger `[models.judge]` model rather than weakening the loop.
- Also added 2026-08-25: **`eh recap --all --force`** — re-recaps every synced chapter in order (existing recaps included), each with per-chapter forced semantics: recap overwritten, rolling context/progress untouched. `--force` without `--all` is rejected (use `--chapter N` for one chapter). Also fixed `--video` to match its help text: the video now renders via an `on_recap` callback right after each chapter's recap commits, instead of after the whole batch. 167 tests green.
- ✅ DONE 2026-08-25: **unified `eh recap` pipeline + progress UI + thinking levels** — `eh video` and `eh translate` are gone; `eh recap` is the single pipeline command (`--translated` runs translation, `--video` renders per chapter right after its recap via `on_recap` and then backfills recapped chapters missing videos; `--voice/--tts-engine/--colorize` moved onto it). New `ui.py` PipelineUI: Rich bars pinned at the bottom (overall chapters + current stage), explicit stage/cache/output logging (page-cache source, per-page translation cache, video stage cache, output paths); plain-line fallback off-TTY. `--thinking low|medium|high` (config `[pipeline] thinking`, default medium) replaces `--no-judge`: low = no judge; medium = text judge, 3 attempts (unchanged); high = **vision-verified judging** (vision model judges recaps against up to 12 sampled chapter pages; page translations judged with the page image attached; 5 attempts; books fall back to text judge). Migration: `eh translate X` → `eh recap X --translated`; `eh video X` → `eh recap X --video`; `--no-judge` → `--thinking low`. 176 tests green.
- ✅ DONE 2026-08-25: **translation judge** — `eh translate` pages now go through the same loop (`judge_translation` in `judge.py`, `_judge_loop` reused from `recap.py`): per page, the judge sees the `{original, translation}` pairs (not the image) and checks language, faithfulness, form, and SFX/credit scope; a fail regenerates with feedback (bounded, keep-first). `eh translate --no-judge` disables; `eh recap --translated --no-judge` propagates. 165 tests green.
  - Live gate (ch 10.6, 6 pt-br pages): PASSED with a caveat — plumbing works end-to-end and keep-first preserved good first attempts, but **qwen3:4b false-rejected 2 of 5 text pages 3/3 times with garbage "issues"** (translation fragments echoed back instead of critiques). Multilingual pair-judging is harder for a 4B model than recap judging; the evidence-quoting rule does not fix it at this size. Cost of a false rejection: 2 wasted vision regenerations on that page. Recommendation: pin `[models.judge] model = "qwen3:8b"` before running the translation backlog, or use `--no-judge` for bulk runs.
